# TabTaskTick Localization (i18n) Plan

> **Status:** Proposed. **Mechanism:** native `chrome.i18n` (display language follows the
> browser locale — no in-app switcher). **Initial locales:** `en` (default) + `es`, `pt_BR`,
> `de`, `fr`, `ja`, `ko`. Expand after string extraction is complete.
>
> All paths below are relative to the extension root (`tabtasktick/`) unless noted.

---

## 1. Decisions & rationale

| Decision | Choice | Why |
|---|---|---|
| Mechanism | Native `chrome.i18n` + `_locales/` | Zero custom runtime; `getMessage()` is synchronous and available in **every** context (service worker, popup, content) so services can localize their own output. |
| Language selection | Browser UI locale | Confirmed requirement. No runtime override, so no message-loader/storage layer needed. |
| Initial locales | en, es, pt_BR, de, fr, ja, ko | GTM priority set. |
| Plurals | `Intl.PluralRules` + per-category keys | `chrome.i18n` has placeholders but **no** plural support. |
| Dates/numbers | `Intl.*` (`toLocaleDateString`, `Intl.NumberFormat`) | Locale-correct without message strings. |
| RTL | Skipped for now | No RTL languages in the initial set. |

**Out of scope (separate, non-code track):** translating the Chrome Web Store
listing (title/short/long description) per locale in the Developer Dashboard. See §11.

## 3. The i18n helper — `services/utils/i18n.js`

Single source of i18n logic (per the services-first rule). Static import only.
Must degrade gracefully when `chrome.i18n` is absent (jest), returning the key so
nothing throws.

```js
// services/utils/i18n.js

/** Get a localized message. subs: string | string[] for $1, $2… placeholders. */
export function t(key, subs) {
  if (typeof chrome !== 'undefined' && chrome.i18n) {
    const msg = chrome.i18n.getMessage(key, subs);
    if (msg) return msg;
  }
  return key; // visible miss in dev; jest mock (§10) returns real en strings
}

/**
 * Plural-aware message. Picks <keyBase>_<category> using Intl.PluralRules
 * for the current UI locale. Categories: zero|one|two|few|many|other.
 * Always author at least `_other`; author `_one` for languages that need it.
 */
export function tPlural(keyBase, count, subs) {
  const locale = (typeof chrome !== 'undefined' && chrome.i18n)
    ? chrome.i18n.getUILanguage() : 'en';
  const cat = new Intl.PluralRules(locale).select(count);
  const all = [String(count), ...(Array.isArray(subs) ? subs : subs != null ? [subs] : [])];
  return t(`${keyBase}_${cat}`, all) || t(`${keyBase}_other`, all);
}

/**
 * Apply translations to static DOM. Walks [data-i18n] for textContent and
 * [data-i18n-<attr>] for attributes (title, aria-label, placeholder, alt).
 * Uses textContent only — never innerHTML — so translations can't inject markup.
 */
export function applyTranslations(root = document) {
  root.querySelectorAll('[data-i18n]').forEach(el => {
    el.textContent = t(el.dataset.i18n);
  });
  const attrMap = { i18nTitle: 'title', i18nLabel: 'aria-label',
                    i18nPlaceholder: 'placeholder', i18nAlt: 'alt' };
  for (const [dataKey, attr] of Object.entries(attrMap)) {
    root.querySelectorAll(`[data-${attr === 'aria-label' ? 'i18n-label' : 'i18n-' + attr}]`)
      .forEach(el => el.setAttribute(attr, t(el.dataset[dataKey])));
  }
}

/** Localize <html lang> + document title. Call once on load. */
export function localizeDocument(titleKey) {
  document.documentElement.lang = (typeof chrome !== 'undefined' && chrome.i18n)
    ? chrome.i18n.getUILanguage() : 'en';
  if (titleKey) document.title = t(titleKey);
  applyTranslations();
}
```

Each surface's module entry (`popup.js`, `panel.js`, `dashboard.js`, `options.js`)
calls `localizeDocument('<surface>_docTitle')` after `DOMContentLoaded`.

## 4. `messages.json` schema & examples

Standard Chrome format. Keys are flat; placeholders are named.

```jsonc
// _locales/en/messages.json
{
  "appName":        { "message": "TabTaskTick" },
  "appDesc":        { "message": "Intelligent tab and task management with collections, rules engine, auto-grouping, and snoozing" },

  "popup_docTitle": { "message": "TabTaskTick" },
  "popup_settings_title": { "message": "Settings" },
  "popup_banner_collections_title": { "message": "Try Collections" },
  "popup_banner_collections_body":  { "message": "Save windows as collections and restore them anytime" },
  "popup_collectionsDetail": {
    "message": "$active$ active, $saved$ saved",
    "placeholders": {
      "active": { "content": "$1", "example": "3" },
      "saved":  { "content": "$2", "example": "12" }
    }
  },

  // Plural example — authored per category
  "snooze_title_tabs_one":   { "message": "Snooze $count$ Tab",  "placeholders": { "count": { "content": "$1" } } },
  "snooze_title_tabs_other": { "message": "Snooze $count$ Tabs", "placeholders": { "count": { "content": "$1" } } }
}
```

Notes:
- `ja`/`ko` have a single plural category (`other`) — only `_other` keys are required there.
- Reserved manifest keys `appName`/`appDesc` are referenced as `__MSG_appName__` (§9).

## 5. Key-naming convention

`surface_context_meaning`, lowerCamel within segments:
- `popup_action_closeDuplicates`, `dashboard_history_emptyState`, `options_backup_frequencyLabel`
- Plurals: `<base>_<category>` → `snooze_title_tabs_one`, `snooze_title_tabs_other`
- Shared/cross-surface strings: prefix `common_` (e.g. `common_cancel`, `common_save`).

## 6. Static HTML pattern (`data-i18n`)

Used for markup authored in `.html` files. Real example from `popup/popup.html`:

```html
<!-- before -->
<button class="settings-btn" id="settingsBtn" title="Settings">…</button>
<div class="banner-text">
  <strong>Try Collections</strong>
  <p>Save windows as collections and restore them anytime</p>
</div>

<!-- after -->
<button class="settings-btn" id="settingsBtn" data-i18n-title="popup_settings_title">…</button>
<div class="banner-text">
  <strong data-i18n="popup_banner_collections_title">Try Collections</strong>
  <p data-i18n="popup_banner_collections_body">Save windows as collections and restore them anytime</p>
</div>
```

The English text stays in the HTML as a readable default/fallback; `applyTranslations()`
overwrites it at load. SVG-only buttons and the logo `alt` get `data-i18n-alt`.

## 7. JS / template-literal pattern (`t()` / `tPlural()`)

Used for strings built in JS — including `innerHTML` templates, which the codebase
uses heavily. Real examples from `popup/popup.js`:

```js
// before
elements.collectionsDetail.textContent = `${activeCollections} active, ${savedCollections} saved`;
elements.collectionsDetail.textContent = 'Error loading';

// after
import { t, tPlural } from '../services/utils/i18n.js';
elements.collectionsDetail.textContent =
  t('popup_collectionsDetail', [String(activeCollections), String(savedCollections)]);
elements.collectionsDetail.textContent = t('common_errorLoading');
```

Rules:
- **Never concatenate** translatable fragments (`'Closed ' + n + ' tabs'`). Use one
  message with placeholders, or `tPlural`.
- For dynamically-rendered `innerHTML` templates, call `t()` **inline** in the template
  literal — do **not** rely on `applyTranslations()` (which only runs on static load).
- **XSS:** keep all HTML markup in code; only inject translated *text* via `t()`. Never
  let a translated string contain markup that lands in `innerHTML`. When in doubt, render
  the node then set `.textContent`.

## 8. Localizing string-producing services

`services/utils/snoozeFormatters.js`, `WindowNameService.js`, and `activityFormatter.js`
emit user-facing text. `snoozeFormatters` is documented as **pure / no Chrome API calls**.

**Approach:** let these services call `t()`/`tPlural()` from `i18n.js`. `getMessage` is
synchronous and the UI locale is a process constant, so output stays deterministic for a
given locale. Update the service's doc contract from "pure, no Chrome API" to "depends only
on the active locale." Tests stay meaningful via the jest `chrome.i18n` mock (§10).

```js
// snoozeFormatters.js — before
export function formatSnoozeTitle({ summary }) {
  return `Snooze ${summary.individualTabCount} Tabs`;
}
// after
import { tPlural } from './i18n.js';
export function formatSnoozeTitle({ summary }) {
  return tPlural('snooze_title_tabs', summary.individualTabCount);
}
```

(Alternative considered and rejected for V1: make formatters return structured data
`{type, count}` and localize in the UI layer — cleaner separation but a larger refactor.
Revisit if formatters grow.)

## 10. Testing & QA

**Jest mock** (so service tests get real English, not keys). Add to jest setup:

```js
// tests/setup/i18n-mock.js — load en/messages.json, implement getMessage + $n subs
import en from '../../_locales/en/messages.json' assert { type: 'json' };
global.chrome = global.chrome || {};
global.chrome.i18n = {
  getUILanguage: () => 'en',
  getMessage: (key, subs = []) => {
    const entry = en[key]; if (!entry) return '';
    const list = Array.isArray(subs) ? subs : [subs];
    return entry.message.replace(/\$(\w+)\$|\$(\d+)/g, (m, name, idx) => {
      if (idx) return list[idx - 1] ?? '';
      const ph = entry.placeholders?.[name]?.content; // e.g. "$1"
      return ph ? (list[Number(ph.slice(1)) - 1] ?? '') : '';
    });
  }
};
```

**CI scripts (npm-runnable):**
- `i18n-extract-check.mjs` — grep all `t('…')` / `tPlural('…')` / `data-i18n*` keys in
  source and assert each exists in `en/messages.json`. Fails the build on a missing key.
- `i18n-key-parity.mjs` — assert every non-`en` locale has exactly `en`'s key set
  (minus plural categories that language doesn't use). Reports missing/extra keys.

**Pseudo-localization:** `i18n-pseudo.mjs` generates `_locales/en_XA/messages.json` from
`en` by accenting letters and padding length ~30% (`"Settings"` → `"[Šéttîngs····]"`).
Set Chrome to that locale to catch untranslated (un-accented) strings and layout overflow
**before** paying for translation. Add `en_XA` to `_locales/` but exclude it from the
store build in `package-ext.sh`.

## 11. ESLint guardrail — `no-hardcoded-ui-string`

New rule in `eslint-plugin-local/`, registered alongside the existing one:

```js
// eslint-plugin-local/index.js
import noAsyncChromeListener from './no-async-chrome-listener.js';
import noHardcodedUiString from './no-hardcoded-ui-string.js';
export default { rules: {
  'no-async-chrome-listener': noAsyncChromeListener,
  'no-hardcoded-ui-string': noHardcodedUiString
}};
```

Rule behavior (start as `warn`, promote to `error` after extraction):
- Flag string literals/template literals containing word characters that are assigned to
  `textContent`, `innerHTML`, `title`, `placeholder`, `aria-label`, or passed to
  `alert/confirm`.
- Ignore: keys passed to `t()`/`tPlural()`, `console.*`, URLs, CSS class strings,
  `import`/path literals, and anything matching an allowlist comment `// i18n-ignore`.
- Scope via `eslint.config.js` overrides to UI dirs (`popup`, `sidepanel`, `dashboard`,
  `options`, `lib/modals`) and string-producing services.

## 12. Date & number formatting

Convert hardcoded formats to `Intl`:
- Dates/relative time in `lib/utils/time.js` and `services/utils/activityFormatter.js`
  → `new Intl.DateTimeFormat(locale, …)` / `toLocaleDateString(locale)`.
- Counts/stats in popup & dashboard → `new Intl.NumberFormat(locale).format(n)`.
- `locale = chrome.i18n.getUILanguage()` (fallback `'en'`).
- Audit for English month/day literals and `${n} active`-style concatenation during §7.

## 14. Translation workflow

1. Freeze `en/messages.json` for a surface once extraction passes pseudo-loc.
2. Machine-translate to the 6 locales with DeepL (preserve placeholders `$name$`/`$1`).
3. Native-speaker review (prioritize es, pt_BR, de — largest GTM audiences first).
4. Run `i18n-key-parity.mjs`; commit per-locale `messages.json`.
5. Keep `en` as the single source; never edit translated files by hand for new strings —
   add to `en`, re-run extract-check, re-translate the delta.

## 17. Risks & gotchas

- **String concatenation** is the #1 i18n bug — must become placeholder messages (§7).
- **`innerHTML` + translations = XSS risk** — only inject text via `t()`, keep markup in code (§7).
- **Plurals:** author `_other` for every count; `ja`/`ko` need only `_other`; `_one` for the rest (§3/§4).
- **Dynamic re-renders** don't get `applyTranslations()` — those templates must use inline `t()` (§7).
- **Service "purity" contract** changes for formatters — update docs, rely on jest mock (§8).
- **Pseudo-locale must be excluded** from the packaged build (§10).
- **Key drift across locales** — gated by `i18n-key-parity.mjs` in CI (§10).
